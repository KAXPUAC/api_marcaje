# Persistencia de refresh tokens

## Recomendación

Para este proyecto se recomienda utilizar **Oracle**, ya que actualmente es la
base de datos principal de la aplicación. Esto evita agregar infraestructura
adicional y permite centralizar autenticación, revocación y auditoría.

Redis sería una alternativa adecuada si posteriormente se requiere un sistema
distribuido de alta velocidad, pero no es necesario para la primera versión.

## Tabla propuesta

```sql
CREATE TABLE AUTH_REFRESH_TOKENS (
    ID                 NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    JTI                VARCHAR2(100) NOT NULL,
    TOKEN_HASH         VARCHAR2(128) NOT NULL,
    USUARIO            VARCHAR2(100) NOT NULL,
    FECHA_EMISION      TIMESTAMP WITH TIME ZONE NOT NULL,
    FECHA_EXPIRACION   TIMESTAMP WITH TIME ZONE NOT NULL,
    FECHA_REVOCACION   TIMESTAMP WITH TIME ZONE NULL,
    REEMPLAZADO_POR    VARCHAR2(100) NULL,
    IP_ORIGEN          VARCHAR2(45) NULL
);

CREATE UNIQUE INDEX UX_AUTH_REFRESH_TOKENS_JTI
    ON AUTH_REFRESH_TOKENS (JTI);

CREATE INDEX IX_AUTH_REFRESH_TOKENS_USUARIO
    ON AUTH_REFRESH_TOKENS (USUARIO);

CREATE INDEX IX_AUTH_REFRESH_TOKENS_EXPIRACION
    ON AUTH_REFRESH_TOKENS (FECHA_EXPIRACION);
```

## Reglas de seguridad

- No guardar el refresh token original en la base de datos.
- Guardar únicamente un hash seguro del token, por ejemplo SHA-512.
- Usar `JTI` como identificador único del token.
- Revocar el refresh token anterior después de una renovación exitosa.
- Guardar el `JTI` del nuevo token en `REEMPLAZADO_POR`.
- Rechazar tokens revocados o expirados.
- Registrar la IP de origen para auditoría.
- No registrar tokens completos en logs.

## Flujo de renovación

1. Recibir el refresh token.
2. Validar firma, tipo, expiración y `JTI`.
3. Calcular el hash del token recibido.
4. Buscar el token activo en `AUTH_REFRESH_TOKENS`.
5. Generar un nuevo access token y refresh token.
6. Revocar el token anterior.
7. Guardar el nuevo refresh token.
8. Confirmar todo dentro de una transacción.

La operación debe ser atómica para evitar que el mismo refresh token pueda
utilizarse simultáneamente en dos solicitudes.

## Cierre de sesión

El endpoint de logout debe marcar el refresh token como revocado:

```sql
UPDATE AUTH_REFRESH_TOKENS
SET FECHA_REVOCACION = SYSTIMESTAMP
WHERE JTI = :JTI
  AND FECHA_REVOCACION IS NULL;
```

## Limpieza de registros

Se recomienda ejecutar periódicamente una tarea para eliminar tokens antiguos:

```sql
DELETE FROM AUTH_REFRESH_TOKENS
WHERE FECHA_EXPIRACION < SYSTIMESTAMP
   OR FECHA_REVOCACION < SYSTIMESTAMP - INTERVAL '90' DAY;
```

## Configuración prevista

```env
ACCESS_TOKEN_EXPIRE_MINUTES=30
REFRESH_TOKEN_EXPIRE_DAYS=30
```
